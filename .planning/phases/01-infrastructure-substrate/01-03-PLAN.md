    Create `docs/decisions/0002-cold-tier-partition-scheme.md` (ADR):

    **Status:** Accepted — 2026-11-12

    **Context:** STORE-03 requires Parquet files on object store with a partition scheme for unlimited retention. PITFALLS.md Pitfall 7 documents two anti-patterns: (1) nested `year/month/day` partitioning defeats partition pruning when only one dimension is filtered, forcing O(N) S3 LIST calls (200x cost in benchmarks); (2) small-file proliferation. The partition layout is set at the first write and cannot be changed without rewriting all historical data.

    **Decision:** The cold-tier S3 key layout is permanently:
    ```
    s3://{bucket}/tenant_id={tenant}/signal_type={metrics|logs|traces}/dt=YYYY-MM-DD/{file}.parquet
    ```
    Hive-style single-column date partitioning, tenant-first ordering.

    **Rationale:**
    - Tenant-first ensures a single-tenant query never scans another tenant's files (PITFALLS.md Pitfall 6 — multi-tenant noisy neighbor).
    - Single-column `dt` enables DataFusion `ListingTable` partition pruning in O(1) metadata lookups for `WHERE dt BETWEEN ...` filters.
    - Matches the ARCHITECTURE.md guidance verbatim; STACK.md Layer 3 Parquet metadata caching assumes this layout.
    - Note: STACK.md also shows a `{year}/{month}/{day}/{hour}/` example in a different table — this ADR explicitly supersedes that example for NewDogRelic; the single-column `dt=YYYY-MM-DD` scheme is authoritative.

    **Consequences:**
    - All writers (IOx flush path, warm-tier compactor, cold archiver) MUST emit files under this exact key template.
    - The warm tier (ADR 0001) and cold tier share this scheme — warm vs. cold differ only by SSD cache residency.
    - Any future need for hour-level granularity must be solved via file-level timestamp statistics (Parquet footer min/max on `ts` column), NOT by nesting a `/hr=HH/` partition.
    - Smoke test `scripts/smoke/cold-partition.sh` includes a negative assertion that `year=.../month=.../day=.../` does not exist; this test becomes a regression guard.

    **Alternatives Considered:** Nested `year/month/day/hour` (rejected — PITFALLS.md Pitfall 7); flat `dt=YYYY-MM-DDTHH/` hour-level (rejected — multiplies small-file count by 24x and provides no pruning benefit DataFusion cannot achieve via Parquet statistics).

    **Links:** PITFALLS.md Pitfall 7; ARCHITECTURE.md component boundaries; ROADMAP Phase 1 success criterion #4.
